Ship AI code with adversarial proof, not vibes.

Veritas turns every AI-written change into a verification loop: mutation testing, property testing, fuzzing, coverage feedback, corpus replay, differential checks, and a confidence score an agent can act on.

Install and use Veritas for this repo.

Run:
cargo install veritas-cli --locked
veritas review-ai
veritas verify --changed --profile ci
veritas score

Use the generated .veritas/ feedback to add or improve tests before marking the change done.

Examples that scale with the risk

Start with one boundary. Keep going until the report has a mutation campaign, fuzz corpus, replay manifest, and selected evolution suite your AI agent can act on.

1. Boundary mutantSmall function, high consequence.
money / permissions 
if refund_cents <= available_cents {
    approve_refund()
}
if refund_cents < available_cents {
    approve_refund()
}
mutation survived

Veritas records the survivor, writes an assertion candidate, persists a repro note, and ranks a test that should kill the mutant.

veritas verify --changed --profile ci
veritas promote-regression --index 0
2. Properties and fuzzingInputs are messy, generated code is optimistic.

A parser accepts totals from invoices. Veritas generates no-panic and deterministic properties, creates Go fuzz targets where possible, and persists minimized repros as corpus entries.

property test fuzz harness corpus entry 
.veritas/assertions/go_0.json
.veritas/corpus/go_0.json
.veritas/repros/go_0.md

The next run can replay the same seed instead of rediscovering it by luck.

3. Behavior replayReview old/new semantics, not just signatures.

For public APIs, Veritas emits replay cases around empty strings, numeric boundaries, booleans, and auth-like roles so AI edits can be compared against expected behavior.

differential replay public API old/new behavior 
.veritas/differential/go_replay.json
.veritas/differential/go_result.json

Replay results become assertion candidates when behavior drift matters.

Veritas combines survivors, uncovered mutants, corpus entries, replay opportunities, and generated harness failures into a ranked suite for the next agent loop.

The testing hub for AI development

Rust and Go work today. The architecture is language-plugin based, with tree-sitter symbol discovery so more languages can join without changing the core verification model.

Mutation testing
Domain-aware mutants for auth, money, parsing, serialization, permissions, booleans, comparisons, returns, and error paths.
Property testing
Generated and discovered properties are scored for assertion strength, determinism, and no-panic coverage.
Fuzzing
Go fuzz targets and Rust repro paths feed persistent corpus entries and replay commands.
Coverage feedback
Coverage gaps become agent-readable prompts for the next test-generation pass.
Differential replay
Public API behavior cases make old/new semantic drift reviewable before acceptance.
Evolution suites
Ranked next-generation candidates tell agents which assertions, seeds, replay checks, or budget fixes to try first.
Confidence score
veritas score rolls findings, survivors, corpus replay, properties, budgets, and generated tests into one readiness signal.
